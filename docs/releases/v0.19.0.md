# v0.19.0

v0.19.0 changes how the skills are installed and nothing else: the messaging
skill is renamed `auu-connect`, the skills go where the command is told, for
Claude Code or for Codex and the agents that read `~/.agents`, and an old
`connect` directory is reported and removed on request. The wire level stays
2 and the relay's schema stays 13, so a v0.19.0 party and a v0.18.2 one are
the same party; there is no upgrade order, and everything
[`docs/releases/v0.18.0.md`](v0.18.0.md) says about upgrading holds for
v0.19.0 as it is. [`docs/client.md`
1.12](../client.md#112-installing-the-skills-for-a-coding-agent) is the
whole of installing the skills, written for a coding agent to follow.

**Going back to v0.18.2.** It is safe, and only the skills differ. v0.18.2
knows the skills as `connect`, `auu-setup` and `auu-relay`, in its own
versions of their files. Its `auu skill ls` does not list `auu-connect`,
says `connect` is absent once it has been removed, and says `auu-setup` and
`auu-relay` differ; its `auu skill install` writes `connect` again beside
`auu-connect`, which is two copies of the messaging skill until one is
removed, and keeps the other two as differing, exit 1, until `--force` puts
its own copies back. Remove `auu-connect`'s directory by hand after going
back, or keep the skills on v0.19.0. What v0.19.0 wrote under
`~/.agents/skills` v0.18.2 does not look at unless given `--dir ~/.agents`.
Nothing else differs.

## What changed

**The connect skill is now auu-connect.** The skill that sends to a
colleague's agent and reads replies is installed as `auu-connect`, beside
`auu-setup` and `auu-relay`, so all three skills carry the program's name.
Its front matter, `auu skill install`, `auu skill ls`, `auu skill
show`, `auu version --json`, the README, the guides and the other two skills
say the new name. `auu skill show connect` is refused, exit 1, in one
sentence that names the new one: `the connect skill is now auu-connect: auu
skill show auu-connect`. An install over an earlier one writes `auu-connect`
and leaves the old `connect` directory where it is, and an agent reads both
until that directory is removed.

**The skills are installed for a target the command is given.** `auu
skill install --target claude` writes them where Claude Code reads them,
`$CLAUDE_CONFIG_DIR/skills`, else `~/.claude/skills`, as every install
did; `--target agents` writes them under `~/.agents/skills`, which Codex
reads, and so does any other agent that reads `~/.agents`; `--dir DIR`
is `DIR/skills` as before, and is refused beside `--target`, since each
names a place. With neither, at a terminal, the command asks which, and
an empty answer or end of file installs nothing; with no terminal, as in
an agent's shell or under `curl | sh`, or with `--json`, it refuses, exit
1, in a sentence that names the command for each target with the
directory each would use, so a coding agent asked to install the skills
has the command to run in the refusal. `auu skill ls` takes the same
target and says the same. An install now says, on its first line, the
directory, whom it is for and the version, then a line per file —
`written`, `replaced`, `already current`, or kept with the reason —
where it said `(updated NAME)`; when nothing was written and a file was
kept its first line is `not all installed:`. `--json` gains `target` and
`version`. The install script passes `--target claude` and names the
agents command when it is done. The one line of a skill this changes is
the setup skill's, which now tells its agent to run `auu skill install
--target claude`, since an agent's shell has no terminal to be asked at.

**An old connect directory is reported, and removed on request.** `auu skill
install` and `auu skill ls` say what the `connect` directory beside the
skills is: `legacy` when it holds exactly the two files an earlier auu
wrote, each in a version the tree held, which the binary knows by digest,
with the command that removes it on the install's last lines; `not-ours`
when it is anything else — a file that differs, one missing or one more, or
not a directory — which nothing touches. Neither fails the install, and
`--json` carries both as `legacy`. `auu skill rm NAME` removes one skill's
directory, `connect` or any of the three, only when every file in it is one
auu wrote, after saying what will go and asking; `--yes` skips the asking.
The copy of one of the three that an older auu wrote is refused as
differing, and `install --force` then `rm` removes it.

## After this release

Small things found on the way, left for a later release:

- The tests' command runner reads what a command prints only after the
  command returns, through a pipe, so a command printing more than the
  pipe holds waits for ever: about 4 KiB on Windows, which is why `auu
  skill show`'s test is not in the Windows list, and 64 KiB on Linux,
  which the reference, at 63 KB, nears (S71).
- The v0.18.2 pair the legacy tests plant would be checked out with CRLF
  on Windows and so not be the shipped bytes; a `.gitattributes` line
  marking them `-text` lets those tests run there (S72).
- The container suite's previous release stays v0.17.0 for this release:
  family O's channel-rule rows, O06 to O09, assert an old party at wire
  level 1, which v0.18.0 ended, so the rows are re-derived for a previous
  release at level 2 and moved to v0.18.2 together, after a `make e2e`
  run shows what that release does (S73).
- `auu peers add` and a `quarantine trust` run at the same moment each
  read the peer list and write it whole, so one can write over the
  other's peer (S69).
- A stream reply whose upload's answer is lost, whose next attempt finds
  the upload finished and opens it again, and whose new open is then
  refused outright, loses the mark that it may be on the relay, so a
  `stream_threshold` changed before the next round could send it again as
  an envelope under a new id (S70).
- `auu watch` runs a goroutine for each relay, and a fault in one ends
  the command rather than that relay's watch (S68).
- A submodule named in decomposed Unicode on macOS fails git's
  `update-index` before `add -A`, and a base holding enough submodules to
  overrun the command line fails the message: both are the handler's own
  doing and fail with nothing run (from 39bd0e3).
- An older relay whose configured public URL ends in a dot refuses a
  token minted by a newer `auu-admin`, a configuration nobody has
  (from 6fd93ff).
- `internal/clientca`'s `Create` and `Load` are called by no program and
  are kept for their tests; they may go.

CI builds the whole tree on Windows and vets it for Windows from Linux,
and on Windows runs the agent, the lock file, the store, the key formats
and identity, the terminal, the name tests of the regular-file and
channel packages against Windows itself, the skills' install, target,
prompt and `rm` name tests, and the agent end to end and `auu serve` as
second processes; the relay and the rest of the suite run on Linux and
macOS, and the kit and the install script on Linux under systemd. The
test that holds the legacy digests to the history needs the whole
history and skips on CI's shallow checkout; it runs on a full clone.
