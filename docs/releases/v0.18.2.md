# v0.18.2

v0.18.2 fixes what two traces of v0.18.1 found. The wire level stays 2
and the relay's schema stays 13, so a v0.18.2 party and a v0.18.1 one
are the same party, and everything
[`docs/releases/v0.18.0.md`](v0.18.0.md) says about upgrading holds for
v0.18.2 as it is. A machine that runs `auu serve` should upgrade first.

**Going back to v0.18.1.** It is safe but for one thing: a home where a
copy of a message to several was moved to another relay by `auu send
--resume --relay` keeps that relay on the copy in the message's sent
record, which v0.18.1, reading every record strictly, refuses by name as
damaged wherever it reads it, listing the sent box or finding the thread
for a follow-up. Remove that record first, or keep the home on v0.18.2.

## What changed

The first trace asked whether any string from the network or from a message
can become a path of its choosing, and found that none can. What it found
instead is eight faults that no message reaches, most of them in `auu
serve`, and a file-open ledger about twenty rows wrong. Each is fixed
here. A second trace
asked whether any byte from the wire can make a program panic, and found
none that can, by four readings and by fuzzing every parser. It found
seven things no message reaches: six are fixed here, the escaped
terminal, the smaller guards, the key file's memory ceiling and the
faults outside a handler below, and one is the upload id's re-check.

**`auu serve` takes less on trust from what a handler leaves.** The
handler writes its worktree and the thread's directory, and serve reads
the worktree after it. As *Serve cannot sandbox the handler* in
[`docs/serve.md`](../serve.md) says, a handler running as serve's own
account can do a great deal anyway; what follows is what keeps a
contained handler, one that can write its worktree but cannot run
commands as serve, from getting serve to run or send something for it.

- Every file serve writes for a run and reads or sends after it is
  under `serve/kept/<thread>/`, which no program is told of: the message
  it hands the handler, what the handler and the hooks print, the
  answer, its patch and its sealed envelope. They were in the thread's
  directory, which the handler writes, where a hard link to a file the
  serve account can read, put at the patch's name, the answer's or the
  envelope's between two attempts, is the file it names, which no open
  refuses, and the retry sent it. An answer an older serve kept in a
  thread's directory is moved into `kept/` once, at the first start, and
  goes out as it was sealed; nothing in a thread's directory is read for
  an answer after that. `kept/` goes with the thread, and one whose
  thread's directory was removed by hand is swept. A side copy's patch
  is still what the worktree holds, a hard link in it included, so a
  contained handler still must not share a filesystem with what the
  serve account can read.
- A kept reply's patch is attached only as the regular file it is. A
  link put in its place is refused by name and the message fails, with
  nothing of the link's target sent. Every read of an attachment holds
  to the same rule, so `auu send --attach` now refuses a symbolic link
  and a pipe, `<(command)` among them, saying what to do instead:
  attach the file the link points at, or write the output to a file.
- The base a side copy's worktree was made from is used only as a
  commit id. One that is not 40 or 64 lowercase hex characters is the
  message's failure, `its base file PATH does not hold a commit id`.
- Serve's git takes the patch from the checkout's own repository, with
  an index of serve's own made from the base and both paths made
  absolute. It reads neither the worktree's `.git` nor the directory git
  keeps the worktree's index in, and runs no filesystem monitor, hook,
  external diff or text conversion. A worktree whose `.git` was changed
  is the message's failure, `its worktree PATH is no longer the git
  worktree serve made`.
- Serve's git starts nothing inside a repository the handler made in
  its worktree. Such a repository is not part of the patch, whether or
  not the base holds a submodule at its path, and a change to a
  submodule's commit does not travel. A file the base holds that the
  handler replaced with a repository goes as deleted.
- A side copy of a sparse checkout is refused, `the checkout DIR is
  sparse`, since its patch would carry every file it leaves out as
  deleted. Serve needs git 2.24 or later, and `auu serve check` says so.
- What a handler or a hook prints, and the reason serve gives for a
  message not answered, reach serve's terminal and journal escaped.
- A message's own id is checked again before serve makes a path from it,
  as its thread id was; only a record written by hand could fail it.

**A relay URL ending in a dot is the relay without it.**
`https://relay.example.` is `https://relay.example`, the same relay, so
adding it beside the relay already there is refused as `already here`
and changes nothing. Before, it made a second relay called
`relay.example.`, which on Windows, where a trailing dot is taken off a
directory's name, was the first relay's directory, and the add a person
confirmed overwrote that relay's record and pinned anchor. A new relay
name may not end in a dot. A home an older version left with a dotted
relay directory still lists and uses it, and its name still counts as
taken.

**Values already checked elsewhere are checked again where they are
used.** The sweep of a mailbox's staged copies, left by an interrupted
stream receive, matches entries by name, so a home whose path holds `[`,
`]`, `*` or `?` no longer reaches a neighbouring directory. The relay skips an upload record whose id is not
an upload id, and refuses one whose recipient is not a fingerprint,
rather than using either as a path. `auu-ca kit` makes its temporary
file new, so a link put at that name does not have the kit, with the
relay's keys, written where it points. `auu-admin --relay` with a URL
this home does not know reads nothing under `relays/` for it. The client
holds the upload id a relay answers with to the shape the relay makes it
in, so a relay cannot steer this client's signed requests to other paths
on itself. A message record under another message's name is refused as
damaged.

**Smaller guards.** Two certificate functions refuse an empty host list,
and a helper that indexed past its string and was never called is gone.
`max_inflight` is at most 65536. A queue row's next try and give-up
times are held to the years a time can be written in, and an outbox
record whose message would not read back is refused where it is read.

**The words about links say what each platform does, and Windows
refuses a link as unix does.** On Linux and macOS a symbolic link is
refused as the last part of a path, not as a directory above it, and an
exclusive create refuses one on every platform. On Windows every open,
and the lock file's, now carries the flag that opens a reparse point as
itself: a symbolic link is refused as a link, with unix's sentence, and
a mount point as a mount point, and any other reparse point is opened
again without the flag, refused if that is not the same file, and
judged as an open always was, so a deduplicated file is read as itself
and a cloud placeholder is refused, as before; the open again neither
creates nor truncates, and a truncate is made again once the file is
judged; the flagged open's own, which Go makes as it opens, empties the
object at the name, the reparse point's own, and never a link's target.
A hard link is the file it names and no open refuses it.

**A serve channel may not be named as a thread.** A read-only channel's
worktree and a side copy's are in one directory, a thread's by its id,
so `auu serve check` refuses a channel named with 32 hex characters, in
either case. On Windows an `exec` line must not name `%AUU_SUBJECT%` or
any other `%AUU_…%`, since `cmd` puts the value in before it reads the
line and a subject may hold `&`, `^` or `|`; the serve guide says so.

**A post the relay has already stored is stored once (S50).** A sender
whose answer was lost on the way back posts the same envelope again, and
the relay stored it twice; `auu` already seals a reply once and posts
the same envelope at every attempt, and this is the relay's half. A
direct post now writes the hash a forward of the envelope does, so a
second post of it within three days is answered with the first post's
id, nothing stored and nothing charged. Five rulings, D137 the
maintainer's and the others made under her window: the window is fixed at three days and not the
courier setting, so a relay with couriers off is held to it too (D133),
or `courier.max_hops` forward_ttls where that is shorter, so a post never
costs more than a forward's longest hash and a short `forward_ttl` leaves
the bound exact (D137);
a carried table at its ceiling stores the post without its hash rather
than refusing it (D134); a post's hash counts against its poster's
carried share as a forward's does, and a poster over its share is stored
without the hash rather than refused, so no few senders can fill the
table couriers need (D135); and a
second poster holding the same sealed envelope is answered with the
first row's id, a number the recipient sees anyway (D136). No schema or
wire change.

**A key file may name at most 1 GiB of Argon2 memory.** A key file
names the Argon2id cost it was written with, and a file edited by hand
could name 4 GiB, which `auu-ca` set out to allocate before it could
refuse the passphrase. The ceiling is now 1 GiB, sixteen times the 64
MiB every file is written with, and a file over it, one at the old
ceiling among them, is refused by its value and the ceiling before
anything is allocated, `auu-ca` naming the file.

**An error that ends a serve run is escaped too.** An error that stops
`auu serve`, from a message's handling or from the sweep of idle
threads, now reaches the terminal through the same escape as a
message's failure line, keeping the exit code it carries. The sweep's
could hold a handler's bytes: a worktree it could not remove was named
by the file in it that would not go, and the handler names its files.
A message's handling had no such route found: git 2.54 replaces a
control byte in its own fatal and error lines, and serve's other errors
there name its own paths, so the escape there guards against a git, a
hook or a later error that does not. A worktree serve no longer
recognises is now said to have had its `.git` or its configuration
changed, since either does it.

**A relay's host and a relay's name are one in any case.** `auu-ca
relay` finds a relay's record by its hosts compared as DNS compares them
and files it under the first host in lower case, so a host given in
capitals is the relay already issued to, with its retired intermediate
kept, where it used to file a second record, or on macOS write over the
first; a record an older `auu-ca` filed under capitals is refused by
name, with the name to rename it to. `auu damaged reopen` reaches the
relay a kept record names in another case, or with a trailing dot, by
the rule a home takes its relay names under, and takes that relay's
fetch lock, and a relay name given to a command in another case is that
relay. A record of a relay removed and added again under another case
stays the removed relay's, as it always has.

**An attachment that changed while it was being sent is named.** A
large message's attachment is hashed and then read again to be sealed,
and one that changed in between is refused, so its recipient never keeps
it as damaged. One that grew past the payload's end, the last file or
an earlier one by more than all after it, was refused as more bytes than
the manifest declares, naming no file; now any change, grown, shrunk or rewritten at
its size, is refused naming the file the moment it shows, and `auu`
says it without the stream package's `stream: malformed:` in front:
`auu: report.pdf changed while it was being sent; send it again`.
In a message to several, where every copy is sealed before any is
posted, a copy that cannot be sealed, for that reason or any other, is
said as the other refusals are, by the copy and the relay it was for,
with the outbox's part: `auu: sealing the copy for carol on work:
report.pdf changed while it was being sent; send it again; nothing was
sent, and the outbox keeps none of this message`.

**A copy moved to another relay is recorded there.** A message to
several keeps one sent record, which names the relay the message went
by; a copy that `auu send --resume --relay` moved, once this home no
longer had that relay, is now recorded with the relay it went to, and
`auu read` says it, so the copy's id stands beside the relay that gave it
(D140, the maintainer's).

**A copy never opened on a relay is said so.** `auu send --resume`
said every record as an upload "opened on" its relay, the copies of a
small message to several and a stream whose upload never began among
them. Those now say they were to be posted to the relay, and the move
to another is held to the same rule as before, since a post whose answer
was lost may already be there: `it was to be posted to work; post it
there with --relay work, or give it up with 'auu outbox drop …' and send
the message afresh`.

**A post too large for the relay is refused in the relay's words.** A
relay refuses a post or forward over its size before it reads a byte and
closes the connection, and drains none of a body over 256 KiB, so an
`auu` still sending met a reset and said a dropped link, wherever an
inline message was larger than the relay takes: a raised stream
threshold, or `--inline`, against a relay whose `max_bytes` is below
`auu`'s inline ceiling. A post or forward over 256 KiB now asks before
it sends its body, as an upload already does, so the relay's `413` and
its sentence arrive instead; a small one does not ask, and a proxy in
front that ignores the ask costs a second. `Expect: 100-continue` is
HTTP/1.1's, and a v0.18.1 relay, being Go's server, answers it as this
one does, so nothing on the wire or the relay changes for it.

**`auu serve` without `--json` stops when it cannot write its report.**
Under `--json` a report line that could not be written, to a full disk or
a closed output, ended the run; the console lines serve prints without
it were dropped, and serve went on writing nowhere. Now they end the run
the same way, at the end of the round, once every message of it is
answered and settled, with the write's own error. A pipe whose reader
has gone ends the process on both, as Go's default for a broken pipe
does.

**A fault outside a request ends that turn, not the program.** A panic
in a goroutine no HTTP handler covers ended the whole process: a
relay's courier worker, the renewal of its own certificate, the agent's
answer to a connection, its expiry and its watch of its socket, and
serve's proxy control socket. None is known to fault; if one does, it
is said once in the log with its stack, and a courier's turn fails and
its neighbour waits a failed attempt's backoff, doubling, a renewal
waits for the next check, a connection closes with what the agent held
locked, and the agent's watch stops the agent cleanly rather than leave
it running deaf to its signals. The relay's database queries close what
they read by a defer as well, since its one connection held by a fault
would stop every request, and what `net/http` says of a fault it
recovered in a handler goes to the relay's log.

**Two channels the disk takes as one are refused.** `auu serve check`
refused two channel names that differ only in case, but not two
spellings of one name, while APFS takes é composed and decomposed as one
directory, under `serve/channels/` and `serve/worktrees/`. The standard
library has no table to say which spellings are one, so `serve check`
and every `serve` start now ask the disk: every channel's name is made,
side by side, in one directory of their own under `serve/`, which goes
after, and a pair the disk takes as one is refused by name. On a disk that keeps them apart
they stay two channels, as they are there. `serve check` now makes
`serve/` if it is not there yet, as a first `serve` does (S63).

**A trust or an rm takes its turn with a fetch.** A fetch acknowledges
what an earlier one delivered and could not acknowledge, and saves each
such record back once the relay has answered; a `quarantine trust` that
moved the record to the inbox while the fetch waited for that answer
found it put back in the quarantine too, and an `auu rm` found it put
back where it was. Both now take the relay's fetch lock, as two fetches
and `auu damaged reopen` do, after trust's question and before anything
is fetched, acknowledged or written, and read the record again once they
have it. A fetch still running after a minute is said as `another auu is
fetching from RELAY; try again in a moment`, at exit 2, with nothing
changed.

**CI shows a kit update refusing a relay that will not stop.** Since
v0.18.0 `install.sh update` ends before its backup when the relay is
still running after its stop; the kit's CI row now proves it: systemd
refuses the stop, update finds the relay still active and says so, and
the relay is left running with nothing of it replaced (S55).

**The ledger and the tests.** The file-open ledger's rows name the
check each path is held to where the trace found them wrong, its test
also finds globs, absolute-path calls, lock files, a program's working
directory, the Windows create and the relay's key pair, and the names
the limit tests feed now include trailing dots and spaces, device names
with a space, UNC paths, alternate data streams, a name in two cases and
the two Unicode spellings of one name. The tests drive a forward's
recipient, an upload's completion and serve's handling of each message
to the checks the rows name.

## After this release

Small things found on the way, left for a later release:

- `auu peers add` and a `quarantine trust` run at the same moment each
  read the peer list and write it whole, so one can write over the
  other's peer (S69).
- An upload attempt that stalls and is then refused holds a relay's
  connection up to two seconds longer, for the read after its answer.
- A courier transport of its own, keeping its connections without ever
  sending a request twice, would spare a relay a handshake for each row
  of a backlog.
- An answer kept as an envelope is sent as a stream under a new id, or
  the other way round, when `stream_threshold` is changed between two
  attempts at it.
- A stream kept for an answer that no longer matches, its asker's key
  changed between attempts, is left in the outbox, where a `send
  --resume` by hand would deliver it beside the new answer.
- `auu watch` runs a goroutine for each relay, and a fault in one ends
  the command rather than that relay's watch (S68).
- A submodule named in decomposed Unicode on macOS fails git's
  `update-index` before `add -A`, and a base holding enough submodules to
  overrun the command line fails the message: both are the handler's own
  doing and fail with nothing run (from 39bd0e3).
- An older relay whose configured public URL ends in a dot refuses a
  token minted by a newer `auu-admin`, a configuration nobody has
  (from 6fd93ff).
- `internal/clientca`'s `Create` and `Load` are called by no program and
  are kept for their tests; they may go.

CI builds the whole tree on Windows and vets it for Windows from Linux,
and on Windows runs the agent, the lock file, the store, the key formats
and identity, the terminal, the name tests of the regular-file and
channel packages against Windows itself, and the agent end to end and
`auu serve` as second processes; the relay and the rest of the suite
run on Linux and macOS, and the kit and the install script on Linux
under systemd.
