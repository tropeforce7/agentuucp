# v0.18.2

v0.18.2 fixes what two traces of v0.18.1 found. The wire level stays 2
and the relay's schema stays 13, so a v0.18.2 party and a v0.18.1 one
are the same party, and everything
[`docs/releases/v0.18.0.md`](v0.18.0.md) says about upgrading holds for
v0.18.2 as it is. A machine that runs `auu serve` should upgrade first.

## What changed

The first trace asked whether any string from the network or from a message
can become a path of its choosing, and found that none can. What it found
instead is eight faults that no message reaches, most of them in `auu
serve`, and a file-open ledger about twenty rows wrong. Each is fixed
here. A second trace
asked whether any byte from the wire can make a program panic, and found
none that can, by four readings and by fuzzing every parser. It found
seven things no message reaches: four are fixed here, the escaped
terminal and the smaller guards below, one is the upload id's re-check,
and two are left for a later release (S58 and S59).

**`auu serve` takes less on trust from what a handler leaves.** The
handler writes its worktree and the thread's directory, and serve reads
the worktree after it. As *Serve cannot sandbox the handler* in
[`docs/serve.md`](../serve.md) says, a handler running as serve's own
account can do a great deal anyway; what follows is what keeps a
contained handler, one that can write its worktree but cannot run
commands as serve, from getting serve to run or send something for it.

- Every file serve writes for a run and reads or sends after it is
  under `serve/kept/<thread>/`, which no program is told of: the message
  it hands the handler, what the handler and the hooks print, the
  answer, its patch and its sealed envelope. They were in the thread's
  directory, which the handler writes, where a hard link to a file the
  serve account can read, put at the patch's name, the answer's or the
  envelope's between two attempts, is the file it names, which no open
  refuses, and the retry sent it. An answer an older serve kept in a
  thread's directory is moved into `kept/` once, at the first start, and
  goes out as it was sealed; nothing in a thread's directory is read for
  an answer after that. `kept/` goes with the thread, and one whose
  thread's directory was removed by hand is swept. A side copy's patch
  is still what the worktree holds, a hard link in it included, so a
  contained handler still must not share a filesystem with what the
  serve account can read.
- A kept reply's patch is attached only as the regular file it is. A
  link put in its place is refused by name and the message fails, with
  nothing of the link's target sent. Every read of an attachment holds
  to the same rule, so `auu send --attach` now refuses a symbolic link
  and a pipe, `<(command)` among them, saying what to do instead:
  attach the file the link points at, or write the output to a file.
- The base a side copy's worktree was made from is used only as a
  commit id. One that is not 40 or 64 lowercase hex characters is the
  message's failure, `its base file PATH does not hold a commit id`.
- Serve's git takes the patch from the checkout's own repository, with
  an index of serve's own made from the base and both paths made
  absolute. It reads neither the worktree's `.git` nor the directory git
  keeps the worktree's index in, and runs no filesystem monitor, hook,
  external diff or text conversion. A worktree whose `.git` was changed
  is the message's failure, `its worktree PATH is no longer the git
  worktree serve made`.
- Serve's git starts nothing inside a repository the handler made in
  its worktree. Such a repository is not part of the patch, whether or
  not the base holds a submodule at its path, and a change to a
  submodule's commit does not travel. A file the base holds that the
  handler replaced with a repository goes as deleted.
- A side copy of a sparse checkout is refused, `the checkout DIR is
  sparse`, since its patch would carry every file it leaves out as
  deleted. Serve needs git 2.24 or later, and `auu serve check` says so.
- What a handler or a hook prints, and the reason serve gives for a
  message not answered, reach serve's terminal and journal escaped.
- A message's own id is checked again before serve makes a path from it,
  as its thread id was; only a record written by hand could fail it.

**A relay URL ending in a dot is the relay without it.**
`https://relay.example.` is `https://relay.example`, the same relay, so
adding it beside the relay already there is refused as `already here`
and changes nothing. Before, it made a second relay called
`relay.example.`, which on Windows, where a trailing dot is taken off a
directory's name, was the first relay's directory, and the add a person
confirmed overwrote that relay's record and pinned anchor. A new relay
name may not end in a dot. A home an older version left with a dotted
relay directory still lists and uses it, and its name still counts as
taken.

**Values already checked elsewhere are checked again where they are
used.** The sweep of a mailbox's staged copies, left by an interrupted
stream receive, matches entries by name, so a home whose path holds `[`,
`]`, `*` or `?` no longer reaches a neighbouring directory. The relay skips an upload record whose id is not
an upload id, and refuses one whose recipient is not a fingerprint,
rather than using either as a path. `auu-ca kit` makes its temporary
file new, so a link put at that name does not have the kit, with the
relay's keys, written where it points. `auu-admin --relay` with a URL
this home does not know reads nothing under `relays/` for it. The client
holds the upload id a relay answers with to the shape the relay makes it
in, so a relay cannot steer this client's signed requests to other paths
on itself. A message record under another message's name is refused as
damaged.

**Smaller guards.** Two certificate functions refuse an empty host list,
and a helper that indexed past its string and was never called is gone.
`max_inflight` is at most 65536. A queue row's next try and give-up
times are held to the years a time can be written in, and an outbox
record whose message would not read back is refused where it is read.

**The words about links say what each platform does.** On Linux and
macOS a symbolic link is refused as the last part of a path, not as a
directory above it. On Windows an open follows a link to a regular file
and the handle judges the file it reaches, while an exclusive create
refuses one on every platform. A hard link is the file it names and no
open refuses it.

**A serve channel may not be named as a thread.** A read-only channel's
worktree and a side copy's are in one directory, a thread's by its id,
so `auu serve check` refuses a channel named with 32 hex characters, in
either case. On Windows an `exec` line must not name `%AUU_SUBJECT%` or
any other `%AUU_…%`, since `cmd` puts the value in before it reads the
line and a subject may hold `&`, `^` or `|`; the serve guide says so.

**The ledger and the tests.** The file-open ledger's rows name the
check each path is held to where the trace found them wrong, its test
also finds globs, absolute-path calls, lock files, a program's working
directory, the Windows create and the relay's key pair, and the names
the limit tests feed now include trailing dots and spaces, device names
with a space, UNC paths, alternate data streams, a name in two cases and
the two Unicode spellings of one name. The tests drive a forward's
recipient, an upload's completion and serve's handling of each message
to the checks the rows name.

## After this release

Small things found on the way, left for a later release:

- `auu quarantine trust` and a fetch run at the same moment over one
  message whose acknowledgement is owed can leave its record in both
  boxes.
- A copy of an envelope, never opened as an upload, is refused on another
  relay with the upload's words, `it was opened on`; and a copy of a
  message to several moved to another relay keeps the first relay's name
  in the sent record.
- An attachment that grew between its hashing and its sealing is refused
  with a sentence that does not name it, and the sentence for a changed
  attachment begins `stream: malformed:`.
- A message to several whose stream fails while it is sealed says less
  than the other refusals do.
- An upload attempt that stalls and is then refused holds a relay's
  connection up to two seconds longer, for the read after its answer.
- An `auu` whose stream threshold is raised above about 1 MiB may read a
  relay's early refusal of a large inline post or forward as a dropped
  link, since only an upload asks before it sends its body.
- A courier transport of its own, keeping its connections without ever
  sending a request twice, would spare a relay a handshake for each row
  of a backlog.
- The kit's `install.sh update` now refuses to go on when the relay did
  not stop; a kit CI row that injects a failing stop will prove it
  (S55).
- `auu serve` run without `--json` still drops the write errors of its
  console lines, where the JSON report now returns them.
- An answer kept as an envelope is sent as a stream under a new id, or
  the other way round, when `stream_threshold` is changed between two
  attempts at it.
- A stream kept for an answer that no longer matches, its asker's key
  changed between attempts, is left in the outbox, where a `send
  --resume` by hand would deliver it beside the new answer.
- On Windows an open follows a link to a regular file. The open flag
  that refuses a reparse point would refuse every cloud file too, so the
  shape for a later release is to open with it, refuse the symbolic link
  and mount point tags alone, and open again without it for any other,
  run first on CI's Windows job (S57).
- A key file edited in the operator's own home can name an Argon2 cost
  of several GiB, which `auu-ca` attempts before it refuses the
  passphrase (S58).
- Nothing recovers from a fault outside an HTTP handler, which ends the
  process (S59).
- Serve's errors that are not one message's, a worktree's among them,
  reach the terminal as they were written; no case was found where one
  carries a handler's bytes, and they will go through the same escape at
  the point they leave a message's handling, with a test (S60).
- A submodule named in decomposed Unicode on macOS fails git's
  `update-index` before `add -A`, and a base holding enough submodules to
  overrun the command line fails the message: both are the handler's own
  doing and fail with nothing run (from 39bd0e3).
- An older relay whose configured public URL ends in a dot refuses a
  token minted by a newer `auu-admin`, a configuration nobody has
  (from 6fd93ff).
- `internal/clientca`'s `Create` and `Load` are called by no program and
  are kept for their tests; they may go.
- A relay host or a relay name the operator gives is compared byte for
  byte where the filesystem folds case, so on macOS `auu-ca relay` for a
  host in another case overwrites the first relay's record, and `auu
  damaged reopen` with a relay name in another case reads that relay's
  kept file; both stay on the operator's own machine (S62).
- `auu serve check` refuses two channels whose names differ only in case
  but not two spellings of one name, while APFS takes é composed and
  decomposed as one directory; the same check will fold the spelling too
  (S63).

CI builds the whole tree on Windows and vets it for Windows from Linux,
and on Windows runs the agent, the lock file, the store, the key formats
and identity, the terminal, the name tests of the regular-file and
channel packages against Windows itself, and the agent end to end and
`auu serve` as second processes; the relay and the rest of the suite
run on Linux and macOS, and the kit and the install script on Linux
under systemd.
